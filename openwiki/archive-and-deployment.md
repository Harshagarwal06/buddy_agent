# Archive Output & Deployment

The graph creates a local publication set. GitHub Actions deploys that set in a
separate step; the graph itself never pushes a branch.

## Files written by the graph

Outside dry-run mode, a successful issue can produce:

- `YYYY-MM-DD.md` from the formatted digest;
- `YYYY-MM-DD.html` from
  [`news_buddy/html_writer.py`](../news_buddy/html_writer.py);
- `YYYY-MM-DD.json` with public article records from
  [`news_buddy/index_writer.py`](../news_buddy/index_writer.py);
- `index.json`, a newest-first manifest of dated JSON files;
- `index.html`, the browsable archive generated by
  [`news_buddy/archive_writer.py`](../news_buddy/archive_writer.py);
- `tokens.css`, `favicon.svg`, and cached image assets required by the pages.

The per-day public JSON keeps title, URL, source, publication date, summary,
tags, importance, and image metadata. It intentionally omits internal prompts,
provider credentials, and SQLite/Chroma state.

An empty digest writes the empty Markdown/HTML issue and refreshes archive
navigation, but there is no dated JSON article record for an empty article
collection.

## Atomic local writes

Markdown and JSON writers use temporary files followed by replacement, reducing
the chance that readers observe a partially written artifact. Archive
generation scans existing dated files so navigation is rebuilt from what is
actually present in the output directory.

## GitHub Pages boundary

[`daily-digest.yml`](../.github/workflows/daily-digest.yml) runs the application
and then stages the current issue into a temporary checkout of `gh-pages`.
That deployment step:

1. requires the dated HTML file to exist;
2. copies the dated HTML, optional JSON, and image directory;
3. regenerates the JSON manifest and archive index in the deployment checkout;
4. commits and pushes only when the staged publication changed.

Manual workflow runs default to `test_run: true`; that mode skips the deployment
step. Scheduled backups inspect `gh-pages` before running the digest and stop
when today's HTML already exists. This preflight guard is part of duplicate-send
prevention and must remain on every backup cron path.

## Consumers

- Browsers consume `index.html` and dated HTML pages.
- The archive's client-side issue search uses data embedded in the generated
  pages.
- The separate [`news_buddy_mcp/`](../news_buddy_mcp/) service reads
  `index.json` and dated JSON records over HTTP.
- Local Chroma semantic search is independent of this public JSON archive.
